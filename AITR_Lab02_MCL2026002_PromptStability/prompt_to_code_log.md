## Code notes (cycle 3)

- `build_tasks(condition, ids, cfg, prompts, ...)` returns tasks ordered by item, then prompt, then sample. `run_id` = `condition|key|prompt|s<k>`. The seed is `1000·item_index + 10·PROMPT_INDEX[prompt] + sample_idx`, with greedy sample 0 and sampled 1..k. PROMPT_INDEX is fixed (P0–P5 → 0–5, question_only → 9, gsm8k_cot → 8), so a seed does not change when other prompts are added.
- `run_tasks(tasks, generate_fn, out, meta)` repairs a partial last line, skips the run_ids already in the file, seeds each task, calls the model, parses the output and appends one record.
- `make_hf_generate_fn(cfg)` loads the pinned model in 4-bit and returns `(fn, meta)`, where fn(messages, decoding) gives `(text, n_in, n_out)`. The library versions and GPU name go into each record.
- `check_condition_allowed` raises `PermissionError` for b0 / main_* / question_only unless `protocol_version` starts with `v1-frozen`.

## Code notes (cycle 2)

- `build_messages(item, prompt_id, prompts)` returns `[{"role": "system", ...}, {"role": "user", ...}]`. The user text is the template filled with `format_context(item.contexts)` and `item.question`. It raises `ValueError` if `long_answer` would appear, and `KeyError` for an undefined prompt (P1–P5 until they are written).
- `parse_decision(raw)` returns `{decision ∈ yes/no/maybe/invalid, conclusion, certainty, parse_status ∈ json/regex/invalid}`. The order is: strip fences, strict `json.loads`, regex on `"decision": "..."`, invalid.
- `parse_gsm8k(raw)` returns the number after the **last** "The answer is" as a normalised string ("18.00" becomes "18", "1,250" becomes "1250"), or None.

## Code notes (cycle 1)

- `load_pqal` returns `{pubid: Item}`, 1,000 entries. `Item.contexts` is a tuple of section strings, and `final_decision` is the gold label. Raises an error on a hash mismatch, an unknown label or a wrong count.
- `load_official_split` reads `test_set.json` and the 10 `dev_set.json` files written by the official script and returns two sorted lists of 500 IDs each. It never re-splits.
- `stratified_sample(ids, labels, n, seed)` sorts the IDs within each label and allocates by largest remainder (100 from 276/169/55 gives 55/34/11). It samples with `random.Random(seed)` in the fixed label order yes, no, maybe, and returns a sorted list. The output therefore depends only on the ID set and the seed, not on the file order.
- `make_sets` writes `configs/ids_{test_all,main,rq3,pilot,gsm8k}.json` and returns counts and hashes.
